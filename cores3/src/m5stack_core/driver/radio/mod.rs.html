2//! Radio bring-up for the ESP32/ESP32-S3 coprocessor.
3//!
4//! The on-package radio is shared between **BLE** and **WiFi** — both are
5//! sub-functions of the same hardware. Each lives in its own submodule and is
6//! gated by a cargo feature, so a binary only compiles in (and pays the RAM cost
7//! of) the radios it actually uses:
8//!
9//! | Feature    | Module    | Provides                                  |
10//! |------------|-----------|-------------------------------------------|
11//! | `ble`      | [`ble`]   | `BleConnector` for the `trouble-host` stack |
12//! | `wifi`     | [`wifi`]  | WiFi controller + scanning                |
13//! | `wifi-sta` | [`wifi`]  | STA + DHCP `embassy_net::Stack` (adds `embassy-net`) |
14//! | `coex`     | —         | software WiFi/BLE coexistence             |
15//!
16//! Coexistence (`coex`) lets BLE and WiFi run at the same time at the cost of
17//! extra RAM (~96 KB reclaimed on ESP32, less on ESP32-S3). It is only compiled
18//! in when an application enables the `coex` feature.
19//!
20//! In all cases `esp_rtos::start(..)` must run before any radio is created — the
21//! radio drivers schedule their work on the esp-rtos executor.
22
23#[cfg(feature = "ble")]
24pub mod ble;
25
26#[cfg(feature = "wifi")]
27pub mod wifi;
